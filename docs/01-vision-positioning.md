# 产品构想与定位

更新：2026-09-30。标注为「假设」的市场判断尚未通过用户访谈或付费行为验证。

## 一句话定位

**FXWeave 让游戏创作者在网页上通过低代码节点图制作所见即所得的 Shader 和效果。** 平台中的 Shader 全部由这套节点工具生成，节点图是可继续编辑的源文件。先做项目方自用版，用工具制作真实作品并打磨创作闭环；再推出面向用户的网页第一版；第二版扩展到面向不同平台及渲染管线的代码生成/编译。

第一版面向用户的简短表达可为：**连节点，实时看效果，生成自己的 Shader。** “带进不同平台的游戏”是第二版要兑现的承诺。

## 为什么存在

游戏开发者经常需要的是「角色受击闪白」「卡牌溶解」「水面扭曲」「场景转场」这样的视觉结果，而不是先写一段底层 Shader 代码。第一版要让创作者在网页里通过节点组合直接看到结果，并能从同一张图生成对应 Shader。第二版处理把结果带入不同项目时的输入素材、透明与采样、作用范围、参数驱动、目标引擎版本、渲染管线和安装步骤。

现有供给有许多强项：Shadertoy 有作品社区，Unity/Godot 有原生创作工具和资产生态，Material Maker 已连接节点编辑器与社区。FXWeave 第一版的机会在于**让网页节点创作、实时预览和生成结果形成可信的一体化工作流**；第二版再以同一源图的目标适配与可核查验证信息增加价值。这些机会仍需实测。[证据与边界](./05-competitive-evidence.md)

## 目标用户与任务

| 用户 | 想完成的任务 | 潜在价值 |
| --- | --- | --- |
| 独立游戏开发者 | 第一版在网页节点工具中制作自己的效果；第二版适配项目目标 | 减少编写底层 Shader 与后续移植返工 |
| 技术美术/视觉设计师 | 用节点做效果，把参数与源图交给开发者 | 可复现、可迭代、可追溯 |
| 游戏 UI/2D 特效创作者 | 对自己的 Sprite、图集、背景和动画预览 | 更早发现裁剪、透明边、采样问题 |
| 后续社区创作者 | 以标准格式发布可派生作品 | 作品传播、署名、未来收入可能性 |
| AI 代理使用者 | 结构化搜索、调参、预览与导出 | 让代理完成可验证的任务，而非只输出代码 |

对外首发人群尚未最终选定。自用版先从项目方近期真正要制作的效果中选一类任务和一个网页渲染后端；2D Web 是候选，不应把 Unity/Godot 导出当成自用版或第一版必需能力。

## 产品承诺

1. **节点是真正的创作入口**：用户能新建、连接、修改节点并生成效果；平台 Shader 均能追溯到可打开的节点源图。
2. **改图即见结果**：连线或调参后在网页中实时预览，并能上传自己的素材、切换背景、尺寸和时间点。
3. **预览与生成一致**：所见效果与同一图生成的 Shader 对应；失败指出节点、输入或当前网页后端限制。
4. **作用位置明确**：不同材质、对象滤镜、全屏后效等有各自输入与输出语义，按版本逐类支持。
5. **第二版适配可检查**：对具体平台、引擎版本及渲染管线生成适配结果与支持状态；“已验证”附测试条件。
6. **分享仍可改**：公开作品保留可编辑源图，后续 fork 保留作者与版本来源链。

这些承诺分版本实现。第一版的“一致”仅针对已支持的网页预览/生成后端；第二版的跨目标适配也不能承诺任意图在 Unity、Godot、Web 或不同渲染管线之间无损运行。

## 范围策略

自用版建议选择**一个网页渲染入口和少量真实效果任务**，先把节点编辑、实时预览、生成、保存/重开做完整，并由项目方持续使用。2D 游戏效果是可行候选，能用透明、图集、像素采样和滤镜区域检验所见即所得。第一版再面向外部创作者打磨易用性和可靠性；第二版增加平台/渲染管线适配。粒子系统和 3D 材质作为不同资产类型单独评估。

不要将所有「Shader」都装进同一种图：粒子包含发射、模拟、生命周期与排序；风格化渲染可能需要灯光、深度与多个 Pass。这些模式可以共用参数、数学节点、作品页与社区基础设施，但需要独立的根节点、能力约束和运行时适配器。

## 差异化与可积累资产

- **节点创作与结果同源**：平台 Shader 都由可编辑图生成；图修改、预览与生成结果保持对应。
- **可直接创作的网页工作台**：节点画布、参数和实时预览构成第一版核心，素材与用途帮助用户判断效果。
- **逐目标验证的适配**：第二版积累平台/管线适配器、限制说明和回归样例。
- **高质量初始目录**：先用自己创作的作品建立格式和内容标准，随后开放创作者。
- **结构化 AI 操作**：同一资产模型供 UI、API、MCP 使用；编辑、预览、诊断和导出可串成一个可检查的过程。

自用版先用团队持续创作检验节点能力与预览/生成一致性；第一版再用外部用户从空图创作成功率及重复使用证明优势；第二版由真实项目采用与适配维护成本证明。漂亮画廊、作品数量或 MCP 接口本身都不足以形成壁垒。

## 商业假设

第一版可测试围绕节点创作效率的付费价值，如私有项目、版本历史、可复用子图、批量变体或协作；第二版可测试经验证的平台/管线适配与团队交付。精选效果包及成熟后的创作者交易是后续选项。先测量“能否从零创作、预览与生成是否一致、作品是否反复修改使用”，再测试跨目标导入和付费意愿；暂不确定价格或抽成。
