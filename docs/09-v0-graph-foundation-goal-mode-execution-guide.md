日期：2026-09-30。状态：给开发负责人执行的首阶段指令。预算 **16 轮**：第 1–12 轮实施，第 13–15 轮仅用于修复与补验证，第 16 轮最终验收。此阶段只建立与渲染目标无关的创作基础；首个效果宿主和网页后端仍待用户决定。

> 在 `D:\WebProjects\FXWeaver` 按本指南逐轮建立 FXWeave 自用版的版本化节点图、类型与语义校验、可编辑桌面画布、撤销重做和工程保存重开。节点图是唯一源文件。每轮做 Debug 与架构自检、运行相应验证，验证通过才提交并推送；推送成功后才能进入下一轮。不得把静态原画、临时解释器或手写 Shader 当成已完成的生成预览。最终提交可复现的演示、测试和验收报告，并通知 `Role.md` 中的规划验收负责人。

## 2. 本阶段要完成什么

1. 一个能在桌面浏览器打开的内部编辑器基础：项目入口、节点库、画布、检查器、保存状态、问题列表；画布与未来预览区域同屏，后者明确显示“渲染目标尚未配置”。布局参考评审原画，不复制其静态假状态。
2. 版本化图文档与节点定义注册表。稳定节点/边/参数 ID、带类型端口、图种类与输出根由注册表定义；图数据与画布位置分开，使布局变化不影响语义构建哈希。最小测试图种类只用于验证基础设施，不冒充正式 Shader 宿主。
3. 纯函数或清晰隔离的图校验与编辑命令：端口存在和类型兼容、输入唯一、必填输入、唯一输出根、无环；添加/删除/移动/连接/断开、属性修改、撤销/重做。无效连接当场拒绝并说明原因，未完成图允许保存。
4. 工程 JSON 的确定性序列化、导入/导出、保存/重开与版本检查。正式文件和浏览器恢复草稿有不同状态；旧版或不兼容文件给出诊断，不静默覆盖。
5. 可重复的单元/集成测试和桌面浏览器 smoke。验收路径是从空测试图添加节点、连接、改值、撤销重做、保存、重开、验证图等价，并制造类型错误与环。测试图只证明编辑器内核，不声称 Shader 已生成。

技术栈由执行者在第 1 轮记录简短 ADR 后选择；核心图模型、校验、序列化不得依赖 DOM、画布组件或未来的单一渲染后端。以 TypeScript 和本地网页工具链为默认方向，避免为了待定的跨平台 V2 建立过大的抽象。任何会固定首个图种类、色彩/Alpha/UV 语义或渲染 API 的决定，须留给下一阶段。

## 3. 本阶段不做什么

- 不生成 Shader，不显示 `Build OK`，不展示看似实时但与图无关的效果预览。
- 不决定 PixiJS、WebGL、Sprite/Container Filter 或其他首个正式宿主；评审原画中的目标只是示例。
- 不做 V2 多平台/管线适配、社区、账号、云同步、AI/MCP 或市场功能。
- 不用手写 Shader 填补节点工具能力；正式作品与 2–3 件真实效果留到目标确定后的阶段。

## 4. 每轮固定工作流

每轮开始读 `git status --short --branch`，说明本轮目标与边界。改动后完成以下自检，并在本轮报告写出结果：

- **Debug 自检**：用最小图或操作路径复现变化；定位失败属于图模型、校验、命令、持久化还是 UI；覆盖成功、失败、空图、不兼容文件和过期草稿等相关状态；UI 变化要有可重复的浏览器 smoke。
- **架构自检**：节点图仍是唯一源；UI 不复制校验或节点语义；节点注册表、图数据、持久化状态与显示状态分层；布局变化不改变语义哈希；不引入本阶段排除的渲染/适配范围；不碰无关文件。
- **验证**：运行与本轮改动相称的类型检查、测试、构建或浏览器 smoke，并记录命令与结果；提交前执行 `git diff --check`。

每轮回复必须包含：轮次、目标、完成内容、Debug 自检、架构自检、验证命令及结果、提交哈希、推送结果、下一轮目标、是否使用缓冲轮。验证失败不得提交；提交或推送失败不得推进下一轮。

## 5. 每轮通过后提交推送工作流

第 1 轮初始化 Git，配置 `onovich/FXWeaver` 远端，确认实际推送通路。SSH 如受本机 relay 限制，可改用同一仓库的 HTTPS；仅对本轮 Git 命令覆盖失效代理，不全局修改用户配置。只提交本阶段相关文件；已有文档与评审图是项目基线，可在首个提交中纳入，但不得把本机缓存、密钥或无关文件加入仓库。

每轮验证通过后执行 `git status --short --branch`、`git diff --stat`、定向 `git add`、提交、推送、再检查状态。记录 commit hash 和远端分支。推送失败时停止并把具体错误报告规划验收会话，等待修复；不能用“稍后推送”跳过阶段门槛。

## 6. 分轮安排

| 轮次 | 目标 | 当轮最低验证 |
| --- | --- | --- |
| 1 | 初始化仓库与可运行网页工程；记录技术栈 ADR，建立 `typecheck`、`test`、`build`、`smoke` 命令入口 | 本地启动、空应用构建、首轮推送成功 |
| 2 | 图 Schema、稳定 ID、语义数据与布局数据分离 | 序列化顺序与布局无关测试 |
| 3 | 节点定义/图种类注册表、端口类型和测试图节点 | 类型签名与注册表测试 |
| 4 | 连接校验：端口、类型、方向、输入唯一 | 有效与无效连接表驱动测试 |
| 5 | 图校验：唯一根、必填输入、无环、未完成图诊断 | 环与缺失输入测试；未完成图可序列化 |
| 6 | 图编辑命令与不可变状态更新 | 添加、删除、连接、断开、移动的命令测试 |
| 7 | 撤销/重做、批量移动、连线替换的原子操作 | 复杂操作往返测试 |
| 8 | 工程文件格式、导入/导出、版本检查与确定性重开 | 保存重开等价、不兼容版本诊断 |
| 9 | 内部工作台布局与状态分区 | 1920×1080 与 1366×768 桌面 smoke |
| 10 | 画布添加/搜索/选择/移动/连线、缩放平移 | 浏览器操作 smoke 与输入拒绝反馈 |
| 11 | 检查器、参数/属性编辑、问题定位 | 编辑、撤销、错误聚焦 smoke |
| 12 | 文件保存/恢复草稿 UI、完整路径整合 | 保存重开与草稿状态端到端 smoke |
| 13–15 | 只修复前 12 轮暴露的缺陷、补关键测试、整理文档 | 每轮说明消耗原因，全部门槛重跑 |
| 16 | 全量回归、演示录证、更新入口文档与验收报告 | 完整矩阵通过、最终提交推送成功 |

第 1 轮确定实际命令实现；此后保持 `npm run typecheck`、`npm test`、`npm run build`、`npm run smoke` 等稳定入口。若使用不同包管理器，在 ADR 中说明并保持同等能力。浏览器 smoke 至少覆盖项目创建、测试图连接、错误反馈、撤销重做、保存重开；不得只检查页面加载。

## 7. PASS 标准

1. 从空图在浏览器中完成一张合法测试图，端口类型、根节点和环约束由同一图核心执行；UI 不保留第二套规则。
2. 无效连线立即解释，未完成图能保存；问题项能定位节点或端口。撤销/重做使图与 UI 状态一致。
3. 保存、关闭、重开后图的语义数据、参数和布局正确恢复；正式文件与本机草稿状态可区分；不兼容文件不破坏当前工程。
4. 全部测试、类型检查、构建、桌面 smoke 通过，并有可复现的演示步骤和最终验证报告。
5. 每轮有可查提交与推送记录。最终报告明确说明：本阶段尚无 Shader 生成或真实实时预览，不能宣称 V0 产品已完成。
