# 阶段计划与验证

更新：2026-09-30。已明确的顺序是：**先做项目方自用版 → 再做对外网页第一版 → 第二版扩展平台/渲染管线适配。** 平台里的 Shader 始终由同一节点工具生成。以下是阶段出口，不是按日期自动推进的排期；执行细节见[可执行路线图](./06-roadmap-proposal.md)和[自用版功能与交互设计](./07-self-use-product-spec.md)。

## R0：自用版——先让团队真正用起来

从项目方近期要制作的效果中选 2–3 个任务，并确定一个网页渲染后端及效果宿主。实现最小节点画布、带类型端口、必要节点、图校验、Shader 生成、使用生成结果的实时预览、参数调节与图保存/重开。内部工具可以粗糙，但不能靠手写 Shader 代码替它完成作品。

**出口**：项目方能用自用版从空图制作数个真实效果，隔天打开继续修改；节点变化与生成 Shader、预览一致。团队在实际创作中记录卡点并持续修正。仅做技术演示或预置模板换色不算通过。

## R1：对外第一版——网页所见即所得创作

在自用版之上改善上手流程、节点搜索、撤销/重做、错误定位、素材导入、预览场景、保存可靠性和文档。项目方用自用版创作的图成为可编辑示例。让外部创作者独立从空图或简单起始图完成效果；先支持一个清晰的网页目标。

**出口**：陌生用户能独立创作、保存、重开和再编辑；预览运行同一节点图生成的 Shader，主要错误能定位到节点。用完成率、首次有效效果耗时和二次编辑行为判断质量，而非示例观看量。

## R2：第二版——平台与管线适配

在稳定图语义上建立中间表示、目标能力检查与代码生成适配器。逐个支持明确的平台/引擎版本；必要时分别支持同平台不同渲染管线。生成 Shader、参数/资源绑定与安装示例，在目标环境编译、运行并对比。

**出口**：同一节点工具至少生成两个明确目标配置的可用结果；不支持能力、降级和视觉差异清楚报告。验证记录包含平台、版本、管线、后端、图类型、测试配置和日期。只吐出代码不算完成。

## R3：社区与商业化

项目方在自用阶段积累由工具生成的作品；第一版可用这些图做精选示例，再按需求开放用户保存、分享、邀请创作者和交易。先验证外部用户是否为创作效率、私有图、版本或协作付费；第二版再验证平台/管线适配与团队交付的付费价值。

**出口**：付费行为对应可重复提供的产品价值；外部公开作品仍有可解析节点源图，授权、审核与验证成本可承受。

## 指标与停线条件

| 阶段 | 核心指标 | 停线或转向信号 |
| --- | --- | --- |
| 自用版 | 团队是否持续用工具创作；真实作品完成数；手写 Shader 绕行次数；图/预览/生成一致性 | 只能做演示，真实效果仍需手写代码；保存重开不可靠；预览与生成结果不同 |
| 第一版 | 外部用户独立创作成功率、首次有效效果耗时、二次编辑与留存 | 用户只能调模板；错误难定位；团队会用但外部用户无法上手 |
| 第二版 | 目标编译/运行成功率、视觉差异、适配维护成本、真实项目采用 | 代码生成后仍需大量手工修复；新增管线造成不可控的特殊处理 |
| 商业化 | 真实报价/付款、持续使用、复购和交付成本 | 只有一次性定制劳动，没有可复用产品需求 |

不要用节点数量、生成 Shader 次数、页面浏览或作品点赞代替这些结果。
