# 官网与创作页：持续视觉优化验收

日期：2026-10-01。用户要求由 subagent 持续优化，规划者验收，不通过退回。

上一轮技术 PASS 仍有效，本次提高视觉、信息架构和实际创作效率的标准。实现者：本会话 subagent `visual_refinement`，主规划者独立验收；原开发会话暂不派发并行改动。

## 目标与判断

首页像一个有真实作品的游戏效果工具；创作页像同一品牌的专业效果实验台。风格应来自图、类型和效果本身，避免只依赖首页插画。

评分不是机械证据：目标为美观性、可用性、风格化均至少 8/10，必须同时通过下面实际检查。不得仅用提高自评分代替迭代。

## 必须解决

1. 首页真实作品与 Hero 质感落差：用公开合成的正常游戏素材，经现有节点图实际生成更有表现力的效果展示。截图、入口对应图、素材与构建一致；现有原示例保留可追溯性。AI 可生成基础素材，但不能把预烘焙效果图片当作真实 Shader 输出。
2. 创作页右侧空间与重复参数：分清运行调参和节点默认/结构编辑，建立清晰标签/折叠/面板分工。1440×900 默认工作流应能看到有用大小的画面与主要参数；选择节点后能方便地编辑，再返回效果观察。当前节点/当前模式明确。
3. 节点可读性：正常编辑尺度标题约14px、端口至少12px，类型与选中状态清楚。全图视图作为概览，用户能明确进入局部可读的编辑状态；改善视口交互时不改变图语义，端口及连线锚点保持正确。
4. 风格统一：官网、节点、预览与面板有同一FXWeave视觉语言；色彩节制，层级和间距精确，减少泛用后台感。主操作约13–14px、重要信息对比度至少4.5:1。

## 交互验收矩阵

- 首页1440及390px无横向溢出，主要创建/打开/示例编辑真实可用。
- 工作台1440×900、1920×1080、1024×900无遮挡、控件可达；主要参数操作不被重复信息挤占。
- 查看全部图 → 定位选中节点 → 可读尺度编辑 → 调运行参数 → 观察预览，能完成完整路径。
- 打开示例、节点连接/拒绝连接、属性修改、撤销重做、保存重开、大预览与Esc/焦点恢复、比较、生成物下载不回归。
- 空/加载/成功/旧画面/错误状态可区分，不能用颜色单独承载含义。
- 图模型、compiler/runtime与存储格式保持既有源头，无手写效果Shader或现成效果替代。
- Unity原项目、.fxweave-local私有工程和素材不修改、不公开。

## 迭代与停止条件

实现者先自看截图并修正，提交实际页面证据供规划者评审。规划者每次给出具体 PASS/FAIL 及最小修正清单；FAIL 返回同一 subagent 继续改，无需用户重新授权。通过后统一提交和推送并记录验收结果。类型检查、单测、完整公共与生产回归最终各跑一次；后续只为具体问题补必要验证。

不能把生成设计稿本身当作实际页面验收证据，也不能宣称人工跨日自用已完成。本轮不做公开部署或新增平台/产品层。
