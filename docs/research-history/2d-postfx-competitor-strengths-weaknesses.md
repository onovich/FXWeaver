# 2D 材质与后效竞品：可验证的优势和限制

核对日期：2026-09-28。资料只取产品方文档和官方源码仓库。这里区分 **对象材质**（改变 Sprite 自身的绘制）、**对象/图层滤镜**（对象或容器画好后处理图像）与**全屏后效**（处理相机输出）。下表的“机会”是产品推论，不能当作已经验证的用户痛点或付费需求。

| 产品 | 官方资料证实的优势 | 官方资料证实的限制或接入步骤 | 对新产品的机会（推论） |
| --- | --- | --- | --- |
| **Unity URP Shader Graph** | 有专门的 Sprite Lit、Sprite Unlit、Sprite Custom Lit 图；另有 Fullscreen 图。Full Screen Pass Renderer Feature 可选透明物体前、常规后处理前、后处理后等插入点，也可要求深度、法线、颜色、运动向量等输入。[图类型](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp.html)、[全屏图](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp-fullscreen.html)、[Full Screen Pass](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/renderer-features/renderer-feature-full-screen-pass.html) | 精灵图和全屏图是不同目标；全屏图还要创建材质并配置 Renderer Feature、插入点及需要的输入。官方明确指出绑定深度/模板缓冲会影响性能。[Full Screen Pass](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/renderer-features/renderer-feature-full-screen-pass.html) | 把“作用对象、所需输入、插入点和安装步骤”放在创建效果之初；导出可安装的 URP 示例及兼容性说明。不能只输出一段 shader 代码。 |
| **Unreal Material Editor 的后效材质** | Material Editor 可创建 Post Process 域材质，接入 Post Process Volume/相机；能读 SceneTexture 和 User Scene Texture，控制位置、优先级及材质实例的过渡。[Post Process Materials](https://dev.epicgames.com/documentation/en-us/unreal-engine/post-process-materials-in-unreal-engine) | 必须设为 Post Process 域，以 Emissive Color 输出，并配置 Blendable；官方建议常见调色、Bloom 等优先用内建 Volume 设置。不同插入点的 HDR/LDR、TAA 和可用缓冲区不同；官方列出 UV、透明度、某些纹理查询等已知限制，每个 Pass 增加开销。[Post Process Materials](https://dev.epicgames.com/documentation/en-us/unreal-engine/post-process-materials-in-unreal-engine) | 用语义明确的“场景颜色、色彩空间、像素尺寸、透明对象”输入，预先提示错误插入点和不支持的输出。对 Unreal 先定位为有限后效配方输出，别承诺所有节点无损迁移。 |
| **Godot CanvasItem / VisualShader / 自定义后效** | CanvasItem 适用于 2D 对象；VisualShader 是节点式作者工具，可查看生成代码。全屏后效可用 CanvasLayer + ColorRect + ShaderMaterial；多 Pass 可叠加 CanvasLayer/ColorRect。[CanvasItem](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html)、[VisualShader](https://docs.godotengine.org/en/stable/tutorials/shaders/visual_shaders.html)、[Custom post-processing](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html) | 官方说明 VisualShader 尚未覆盖文本 shader 的全部功能。2D 的 `hint_screen_texture` 首次使用时会复制屏幕，后续使用者默认仍读第一次的拷贝；多个重叠效果要通过 BackBufferCopy 安排次序。多 Pass 还需配置场景节点。[VisualShader](https://docs.godotengine.org/en/stable/tutorials/shaders/visual_shaders.html)、[Screen-reading shaders](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html)、[Custom post-processing](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html) | 可导出 `.gdshader` 加完整场景节点配方，并对多 Pass 的拷贝顺序作静态检查。 |
| **Construct 3 Effects** | 浏览器内完成编辑和预览；官方提供 80 多种效果，可施加于对象、图层、布局，按顺序串联并在运行时修改参数。[Effects](https://www.construct.net/en/make-games/manuals/construct-3/project-primitives/objects/effects) | 免费版每项目限两个效果；布局上不能使用需与背景混合的效果。官方提醒效果太多会拖慢性能，大量实例分别套同一效果时有时应改用图层，静态效果应预先烘焙。自定义效果要通过 Addon SDK 适配 WebGL GLSL 与 WebGPU WGSL。[Effects](https://www.construct.net/en/make-games/manuals/construct-3/project-primitives/objects/effects)、[WebGPU shaders](https://www.construct.net/en/make-games/manuals/addon-sdk/guide/configuring-effects/webgpu-shaders) | “预设数量”和“浏览器操作”并非明显空白。更具体的机会是每个效果显示实际作用范围、实例数影响，以及静态烘焙/图层合并建议。 |
| **GDevelop 效果** | 有对象与图层效果，内置选效果、调参数流程；可在预览运行时应用修改，用事件启停或调整参数。[Object effects](https://wiki.gdevelop.io/gdevelop5/objects/effects/)、[Layer effects](https://wiki.gdevelop.io/gdevelop5/interface/scene-editor/layer-effects/) | 官方的图层效果工作流要求进入图层效果窗口，选类型和参数，再启动预览；通过事件动态调整时，要手填图层、效果及参数名称，名称区分大小写。图层效果作用于整层，场景背景色本身不能套效果。[Layer effects](https://wiki.gdevelop.io/gdevelop5/interface/scene-editor/layer-effects/) | 直接操纵预览中的对象并暴露可复制的类型化参数绑定，比再做一个下拉列表更有机会改善体验。 |
| **PixiJS Filters** | Filter 能加到 Sprite 或 Container，多滤镜可按顺序叠加；开发者能创建自定义 shader，WebGL/WebGPU 两种 renderer 都有接口。[Filters](https://pixijs.com/8.x/guides/components/filters)、[Scene objects](https://pixijs.com/8.x/guides/components/scene-objects) | 官方说明 Filter 是对象内容渲染后的逐像素处理，频繁使用会增加内存与计算成本；自定义 Filter 要提供 shader 程序、资源和运行时 uniform 更新。双 renderer 支持需要对应的 WebGPU 程序。[Filters](https://pixijs.com/8.x/guides/components/filters)、[Scene objects](https://pixijs.com/8.x/guides/components/scene-objects) | 面向开发者输出可运行的 Filter + 参数 API + 最小集成示例，并诚实标注 WebGL/WebGPU 支持；将 Filter 与真正的 Sprite 渲染材质分开。 |
| **Phaser FX** | 内置 Bloom、Blur、Glow、Pixelate、Vignette、Wipe 等效果；可按顺序叠加，施加于常见 Game Object 或 Camera。Texture 类对象还有 Pre FX，全部对象和 Camera 有 Post FX。[FX](https://docs.phaser.io/phaser/concepts/fx) | 官方明确 FX 仅适用于 WebGL，Canvas 模式不可用。Pre FX 的对象类型有限；自定义后效需要接入 Phaser 的 PostFXPipeline 和 Render Targets。[FX](https://docs.phaser.io/phaser/concepts/fx)、[PostFXPipeline](https://docs.phaser.io/api-documentation/3.88.2/class/renderer-webgl-pipelines-postfxpipeline) | 把 Phaser 作为独立导出后端，并自动生成 Pipeline 注册、挂接与销毁代码；预览中模拟对象 FX 与 Camera FX 的不同裁剪范围。 |
| **ShaderFrog** | 浏览器 shader 图的相关竞品。官方 core 仓库说明能把图编译成 GLSL 与元数据，并给出 Three.js `FrogMaterial` 的导出/集成接口。[ShaderFrog core](https://github.com/ShaderFrog/core) | 其官方说明强调输出是 GLSL 与元数据；接入其他引擎需要实现 engine plugin，core graph API 标为实验性。现有 Three.js 集成使用 `onBeforeCompile` 及 shader 注入，这不等于通用可移植材质文件。[ShaderFrog core](https://github.com/ShaderFrog/core) | 差异化应落在“目标后端实测集成”，而非宣称原始 GLSL 本身就跨引擎。 |
| **NixieFX** | 免费浏览器粒子 VFX 编辑器，有节点材质图、PixiJS/Three.js 后端、导出包及逐后端支持报告。[官方运行时参考](https://nixiefx.com/vfx-runtime-docs/) | 其核心交付是粒子系统。概览将 PixiJS 材质概括为烘焙纹理和逐粒子通道，详细手册还描述 PixiJS Tier 2 动态图通过粒子 Shader 运行；因此不是“只有烘焙”，也不能视为通用 Sprite 或全屏效果导出器。[官方运行时参考](https://nixiefx.com/vfx-runtime-docs/) · [编辑器手册](https://nixiefx.com/editor-manual/) | 不能只借鉴后端支持报告；产品应清晰区分 Sprite 效果、全屏后效和粒子 VFX。 |

## 跨产品的设计结论（推论，待用户测试）

1. **先选效果作用范围，再出现节点。** 对象材质、对象滤镜、图层滤镜、相机后效所能读的纹理、可用混合模式及部署步骤各异。Unity、Godot、PixiJS、Phaser 的官方接口都体现这一区别；统一画布可以共用节点 UI，但输出目标必须显式区分。[Unity](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/prebuilt-shader-graphs-urp.html)、[Godot](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html)、[PixiJS](https://pixijs.com/8.x/guides/components/filters)、[Phaser](https://docs.phaser.io/phaser/concepts/fx)
2. **把“能看到效果”提升为“能在目标项目复现”。** 每个导出后端至少附运行时代码、资源、参数接口、目标版本和不支持项报告。ShaderFrog 的引擎插件边界与 NixieFX 的后端支持报告都说明，仅有图或 GLSL 还不足以定义交付。[ShaderFrog core](https://github.com/ShaderFrog/core)、[NixieFX](https://nixiefx.com/vfx-runtime-docs/)
3. **预览真实的失败情境。** 用户应能切换自己的透明 Sprite、重复实例、图层、背景、像素采样、不同分辨率和动态参数；展示对象边缘、裁剪、叠加顺序与多 Pass 成本。Construct 官方性能建议、Godot 的屏幕拷贝语义和 Unreal 的 UV/TAA 限制为这些检查提供了依据。[Construct](https://www.construct.net/en/make-games/manuals/construct-3/project-primitives/objects/effects)、[Godot](https://docs.godotengine.org/en/stable/tutorials/shaders/screen-reading_shaders.html)、[Unreal](https://dev.epicgames.com/documentation/en-us/unreal-engine/post-process-materials-in-unreal-engine)
4. **第一版更适合选一个后端做端到端承诺。** 例如 PixiJS WebGL Sprite/Container Filter：上传素材、修改参数、实时预览、导出可运行示例，再测用户是否愿意为节省集成时间付费。Unity/Godot/Phaser 后端可以逐个加入；以上竞品资料并未证明“任意节点一键跨引擎”等价输出可行。[PixiJS](https://pixijs.com/8.x/guides/components/filters)、[Unity](https://docs.unity3d.com/6000.0/Documentation/Manual/urp/renderer-features/renderer-feature-full-screen-pass.html)、[Godot](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html)

此文只核对公开功能与技术边界，没有进行竞品实机可用性测试、目标用户访谈或付费意愿验证。价格会变化，故未用未经本次核实的数字作比较。
