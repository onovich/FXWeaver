# 2D 材质与后效工具：竞品核对

核对日期：2026-09-28。只使用产品官方文档、项目官方源码仓库及产品方说明。这里的“材质”指精灵或 UI 对象的逐像素着色；“后效”指先渲染对象、图层或整帧，再处理所得图像；“粒子 VFX”还包含发射、运动、生命周期等系统，不能等同于 shader。

| 工具 | 作者体验和作用范围 | 可交付内容与边界 |
| --- | --- | --- |
| **Unity URP Shader Graph** | 内置节点图；有 Sprite Lit、Sprite Unlit、Sprite Custom Lit，以及单独的 Fullscreen Shader Graph。前者对应精灵材质，后者对应全屏效果。URP 的全屏 Pass Renderer Feature 将材质插入渲染流程；2D Renderer 支持 Renderer Features。[Shader Graph 类型](https://docs.unity3d.com/ja/6000.0/Manual/urp/prebuilt-shader-graphs-urp.html)、[全屏 Pass](https://docs.unity3d.com/ja/6000.0/Manual/urp/renderer-features/renderer-feature-full-screen-pass.html)、[2D Renderer](https://docs.unity3d.com/kr/Packages/com.unity.render-pipelines.universal%4015.0/manual/2DRendererData-overview.html) | 产物是 Unity/URP 项目内的 Shader Graph、Material 和 Renderer Feature 设置；它们本身不是可直接移植到 Web/Godot 的通用 shader。[精灵图创建步骤](https://docs.unity3d.com/ja/6000.0/Manual/urp/ShaderGraph.html)、[全屏 Shader Graph](https://docs.unity3d.com/cn/6000.0/Manual/urp/prebuilt-shader-graphs-urp-fullscreen.html) |
| **Godot VisualShader** | 引擎内节点图，能预览材质和查看生成的 shader 代码；官方明确说 VisualShader 没覆盖脚本 shader 的所有功能。CanvasItem shader 用于 2D 对象和 UI。后效可用全屏 ColorRect 读取 screen texture，多 Pass 需叠放 CanvasLayer/ColorRect。[VisualShader](https://docs.godotengine.org/en/4.4/tutorials/shaders/visual_shaders.html)、[CanvasItem](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/canvas_item_shader.html)、[后效教程](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html) | 产物是 Godot 自身的 VisualShader/ShaderMaterial 或 `canvas_item` shader 及场景节点设置；对跨引擎导出没有天然保证。后效的屏幕纹理访问和多 Pass 由 Godot 的渲染机制决定。[VisualShader](https://docs.godotengine.org/en/4.4/tutorials/shaders/visual_shaders.html)、[后效教程](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html) |
| **Construct 3** | 浏览器游戏编辑器内提供 **80 多种**预置效果，可挂在对象、图层、布局上并按顺序串联，参数可在运行时改变；免费版每个项目限用两个效果。开发者可写自定义 Effect 插件，但需为 WebGL 编写 GLSL、为 WebGPU 另写 WGSL。[效果手册](https://www.construct.net/en/make-games/manuals/construct-3/project-primitives/objects/effects)、[Addon SDK](https://www.construct.net/en/make-games/manuals/addon-sdk)、[Effect 配置](https://www.construct.net/en/make-games/manuals/addon-sdk/guide/configuring-effects) | 编辑成果留在 Construct 项目；自定义效果可包装成 `.c3addon`。这是“快速套用和调参”的强竞争者，也显示跨 WebGL/WebGPU 生成需处理两套语言。[Addon SDK](https://www.construct.net/en/make-games/manuals/addon-sdk)、[WebGPU shader](https://www.construct.net/en/make-games/manuals/addon-sdk/guide/configuring-effects/webgpu-shaders) |
| **GDevelop** | 引擎内有图层效果，适合快速改变整层画面；其官方开发文档把自定义效果称为 PixiJS filter，需要在扩展中写代码并注册。其编辑方式更接近选效果、调参数，而不是官方文档中的独立材质节点图。[图层效果](https://wiki.gdevelop.io/gdevelop5/interface/scene-editor/layers-and-cameras/)、[自定义效果实现](https://github.com/4ian/GDevelop/blob/master/newIDE/README-extensions.md) | 产物随 GDevelop 项目/运行时使用；官方文档没有说明通用 shader 跨引擎导出。GDevelop 自身运行时使用 PixiJS/Three.js。[项目仓库](https://github.com/4ian/GDevelop)、[自定义效果实现](https://github.com/4ian/GDevelop/blob/master/newIDE/README-extensions.md) |
| **PixiJS + pixi-filters** | Web 2D 开发者的代码工具：Filter 可作用于 Sprite/Container，多个 Filter 按数组顺序执行。官方和社区包有 blur、pixelate、glitch、outline 等效果；自定义 Filter 需要 shader 和资源。不是面向非程序员的节点作者工具。[Filter 指南](https://pixijs.com/8.x/guides/components/filters)、[滤镜库](https://github.com/pixijs/filters/blob/main/README.md) | 产物是项目中的 PixiJS Filter 实例及 GLSL/WGSL 代码。若同时支持 PixiJS 的 WebGL 与 WebGPU renderer，需要提供相应程序；只提供一个时另一个 renderer 不可用。[Shader API](https://pixijs.download/dev/docs/rendering.Shader.html)、[Filter 指南](https://pixijs.com/8.x/guides/components/filters) |
| **PlayCanvas Shader Editor** | 直接的“浏览器节点图生成 shader 材质与效果”竞品；官方说明把图转换为运行时 shader，项目文件包含 graph、material、texture 和 preview asset。[介绍](https://developer.playcanvas.com/shader-editor/introduction/)、[文件处理](https://developer.playcanvas.com/shader-editor/overview/file-handling/) | 交付内容面向 PlayCanvas 运行时；它证明浏览器作者工具已存在，因此“网页 + 连线”本身不足以差异化。[介绍](https://developer.playcanvas.com/shader-editor/introduction/)、[文件处理](https://developer.playcanvas.com/shader-editor/overview/file-handling/) |
| **NixieFX** | 2026 年官方文档描述为免费浏览器粒子 VFX 编辑器，含节点材质图、PixiJS 与 Three.js 预览、后端兼容性报告。核心是粒子发射器与特效时间线，属于相邻领域。[功能说明](https://nixiefx.com/vfx-runtime-docs/)、[编辑器手册](https://nixiefx.com/editor-manual/) | 导出运行时 JSON/资源包，配套 `nixie-fx` 运行时。概览将 PixiJS 材质概括为烘焙纹理和逐粒子通道；详细手册还描述 PixiJS Tier 2 动态材质图经批量粒子 Shader 运行。因此不能把它称为“只支持烘焙”，但其交付仍面向粒子效果，而不是通用 Sprite 或全屏后效。[功能说明](https://nixiefx.com/vfx-runtime-docs/) · [编辑器手册](https://nixiefx.com/editor-manual/) |
| **PixiEditor 2.0** | 桌面端开源 2D 图像编辑器，也有节点式 Shader Graph 和代码 Shader Node，定位更偏 2D 素材制作。[产品方进展](https://pixieditor.net/blog/2025/03/19/q1-status/) | 所核对的产品方材料没有宣称导出可直接运行的 Unity/PixiJS/Godot shader；不应把图像输出或素材导出当成运行时材质导出。[产品方进展](https://pixieditor.net/blog/2025/03/19/q1-status/) |

## 对产品边界的推论

1. **先确定交付物。** `SpriteMaterial`、`Layer/ScreenEffect`、`ParticleVFX` 应是不同图类型或明确的输出目标。同一个模糊的“2D shader”导出按钮会掩盖渲染输入、纹理坐标、透明混合、多 Pass、背后画面采样等差异。这个划分由 Unity 的精灵/全屏图分离、Godot 的 ColorRect 后效流程、Construct 的对象/图层/布局效果、NixieFX 的粒子系统差异推得。[Unity](https://docs.unity3d.com/ja/6000.0/Manual/urp/prebuilt-shader-graphs-urp.html)、[Godot](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html)、[Construct](https://www.construct.net/en/make-games/manuals/construct-3/project-primitives/objects/effects)、[NixieFX](https://nixiefx.com/vfx-runtime-docs/)
2. **更可信的突破点是“生成后真的能用”。** 让用户上传自己的精灵、序列帧与背景，在同一编辑器中看透明边缘、像素采样、动画和低端设备效果；导出时明确 PixiJS/WebGL、Unity URP、Godot 各自支持的节点与安装步骤，并给兼容性报告。这是基于上表的产品推论，仍需用户访谈验证。
3. **MVP 最窄可选“Web 2D Sprite 效果 + PixiJS Filter 导出”，随后扩展到图层后效。** 原因是 PixiJS 的 Filter API 和应用范围清晰；复杂多 Pass/全屏效果、Unity 2D Lit、Godot screen texture 均增加新的渲染语义。PixiJS Filter 是对象渲染后的滤镜，不应宣传成 PixiJS 原生 Sprite 材质。此处为工程范围建议，不表示这些平台必然难以支持。[PixiJS Filter](https://pixijs.com/8.x/guides/components/filters)、[Unity 2D](https://docs.unity3d.com/ja/6000.0/Manual/urp/prebuilt-shader-graphs-urp.html)、[Godot 后效](https://docs.godotengine.org/en/stable/tutorials/shaders/custom_postprocessing.html)
