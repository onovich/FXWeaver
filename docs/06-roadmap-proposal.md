# FXWeave 可执行路线图（修订建议稿）

更新：2026-09-30。用户明确的顺序是：**先做项目方自用版（下文暂称 V0），用同一低代码节点工具制作真实 Shader/效果；再做面向外部用户的网页 V1，提供所见即所得的节点创作；V2 在代码生成/编译阶段生成不同平台的适配版本，必要时分别支持不同渲染管线。** 平台中的 Shader 均由这套工具生成。V0 Phase 0 节点图与编辑器基础已通过验收；首个网页目标已选为 PixiJS 8 WebGL Sprite/Container Filter，首批已定 [03 径向燃烧、05 局部溶融与 09 单形态局部全息扫描](./13-v0-2d-effect-candidates.md)，其 [Phase 1 执行指南](./15-v0-generated-filter-goal-mode-execution-guide.md)预算为 **20 轮**。V2 目标平台和商业模式仍待确定。

本文时间仅作资源参考：若约有 2 名全职工程师和兼职产品/技术美术支持，可把 V0 自用版看作前约 3 个月、对外 V1 看作随后约 3–4 个月、V2 首批适配目标看作再随后约 4–6 个月的工作。实际推进以通过门槛为准。已有的[阶段验证文档](./04-roadmap-validation.md)给出更简短的出口定义。

## 产品定位与版本边界

| | V0：项目方自用 | V1：对外网页节点创作 | V2：平台/管线适配 |
| --- | --- | --- | --- |
| 用户任务 | 团队用工具从空图制作真实效果，边使用边修正节点与生成链路 | 外部创作者独立连节点、换素材、实时预览、生成并保存效果 | 用同一节点源图选择目标平台/引擎版本/渲染管线，生成适配代码与资源绑定并验证 |
| 核心资产 | 带类型、可保存重开的节点图和从图生成的网页 Shader | 同一源图，加稳定交互、示例、文档与可靠存储 | 同一源图，加目标能力声明、适配器与验证记录 |
| 完成标准 | 团队持续用它制作数个作品；**改图即改预览**；不靠手写 Shader 补完 | 陌生用户能独立创作、重开和再编辑；预览与生成一致 | 目标工程能运行；不支持/降级及视觉差异有记录；每条管线分别说明支持情况 |
| 边界 | 内部使用，界面可粗糙；先支持一个网页渲染后端 | 完整社区、多个引擎/管线不构成 V1 验收 | 先完成少量明确目标配置，不宣称任意节点图无损跨平台 |

项目方在 V0 用产品自身制作的效果，是 V1 的可编辑示例和第一批内容。**节点编辑器始终是主要创作入口**；示例帮助学习，不能让产品退化成模板换色器。V2 复用 V0/V1 的图语义，不要求每个平台拥有一套新的手工制作 Shader。

## 阶段计划

| 阶段 | 参考时间 | 必做工作 | 阶段出口 |
| --- | --- | --- | --- |
| **R0 V0 自用版** | 第 1–12 周 | 从团队近期需求选 2–3 个效果；做最小节点画布、图模型、Shader 生成、实时预览与保存重开，并用工具完成这些效果 | 团队能持续用它创作和修改真实作品；不靠手写 Shader 绕行；预览与生成一致 |
| **R1 V1 封闭试用** | 第 13–20 周 | 根据自用卡点改善节点搜索、撤销/重做、错误定位、素材导入、上手引导和可靠存储；邀请外部创作者完成任务 | 陌生用户能独立完成效果并保存重开；主要失败有可解释的诊断 |
| **R2 V1 公开版** | 第 21–28 周 | 完成示例图、文档、图版本/迁移、多预览场景与稳定性；项目方持续用同一工具做新作品 | 外部用户能再次修改自己的效果；同一图的预览与生成结果对应；达到公开试用质量 |
| **R3 V2 首批适配目标** | 第 29–44 周 | 稳定中间表示、目标能力模型、目标代码生成/资源绑定、最小安装示例、两组目标配置的构建与视觉验证 | 同一节点工具可生成至少两个明确目标配置的可用结果；不支持能力和视觉差异可解释 |
| **R4 V2 扩展与商业试验** | 第 45–56 周及以后 | 根据用户需求增加目标平台或同平台第二渲染管线；测试专业创作/适配收费；按实际使用发展分享与创作者供给 | 新适配器维护成本可承受；付费理由有真实交易或明确拒绝证据 |

周数不自动触发下一阶段。如果 V0 还不能支持团队用节点图持续制作真实效果，就先修自用版；V1 未证明外部创作可用时，不急于扩到 V2。已选的 PixiJS 8 WebGL 对象/容器 Filter 是 V0 的**首个网页目标**；它处理已绘制对象/容器，不能代称全部 Shader 类型。[PixiJS Filter 文档](https://pixijs.com/8.x/guides/components/filters)

## V0 自用版及 V1 的产品与技术工作

### R0：先做自用版并用它创作

从项目方近期确实要做的效果中选 2–3 个，确定一个网页渲染后端和首个效果宿主。建立最小内部工作台：从空图添加/连接带类型节点，修改参数，生成 Shader，实时预览，保存并重开。团队每次制作这些效果都用工具本身完成，记录缺失节点、编译错误、卡住的操作与不得不手写代码的地方，按真实使用修正。2D Web、对象滤镜、材质等只是切口候选。

R0 同时锁定第一类图的 Shader 输入输出、坐标/UV、颜色与透明、时间和纹理采样语义。建立最小链路：节点图 → 类型/语义校验 → Shader 生成 → 浏览器编译 → 实时渲染。浏览器预览必须运行同一图生成的 Shader。自用版的出口是团队能重复完成真实效果，而不只是技术演示。

### R1：把自用工具打磨给外部创作者

- 用自用版积累的真实图和错误记录确定节点搜索、撤销/重做、画布导航、参数说明及节点级错误定位的优先级。
- 保留可从空图创作的路径，补齐素材导入、可靠保存、导入/导出源图与基础上手说明。失败时可保留最后一次成功画面，但明确标记预览已过期。
- 邀请 5–8 位目标创作者带自己的素材试用，观察寻找节点、连接、定位错误、调参、预览、保存和隔天继续编辑；记录从空图到首次有效效果的时间及放弃点。
- 项目方继续用同一工具制作示例。**所有示例 Shader 也必须由产品节点图生成。**

### R2：让对外创作可反复使用

支持真实素材、透明背景、深浅背景、不同分辨率/时间点；按首发图类型加入必要的图集或像素采样场景。提供源图保存、导入/导出和版本迁移；用户能查看生成代码及错误，但不需要手写代码才能完成效果。可复用子图、参数预设、快捷操作和私有云存储按观察到的重复需求排序。

V1 可以有团队制作的精选示例与轻量分享，公开投稿、收藏、评论和交易不构成这一版的发布门槛。作品若公开，必须附平台可打开的源图；更新产生新版本。

**V0 自用出口**：团队用工具从空图做成至少 2–3 件确实需要的效果，之后还能修改和复用；生成 Shader 不依赖手工补丁；保存重开与实时预览一致。记录每次手写代码绕行和缺失节点。**V1 试用指标（建议试验阈值，不是市场事实）**：首批 5 位陌生用户中至少 4 位能独立从空图或简单起始图完成有效变体；保存重开后图与预览一致；主要编译错误能指向节点；用户隔天愿意继续修改，而非只观看示例。还需记录时间、放弃点、崩溃与预览失配。

## V2 的编译与适配工作

V2 不应只做 GLSL/WGSL/HLSL 字符串翻译。一个目标配置至少包括：**平台/引擎及版本、渲染管线、图类型/作用范围、图形后端**。适配器为该配置声明节点能力、输入资源、生成文件、参数绑定、挂载方式及限制。即使是同一引擎的不同管线，也可能需要不同 Shader、Pass 和运行时装配；是否列入首批目标由用户需求决定。

从 V1 图语义建立可验证的中间表示，再逐目标降低到 Shader 和运行时文件。首批选择至少两个明确目标配置，其中可包含 V1 网页目标；若要证明跨平台价值，另一目标应是不同平台或引擎。每个目标都完成：生成代码编译、最小目标工程运行、关键参数响应、代表性素材与截图对比、已知差异说明。能力报告为 `supported`、`partial` 或 `blocked`，不可把“生成成功”写成“项目可用”。

第一版单后端时也应保留图类型、语义与生成器边界，为 V2 留空间；但不必在 V1 提前实现所有后端抽象。V2 目标优先级由创作者的真实项目决定，暂不指定 Unity、Godot、Phaser 等必做顺序。

## 商业化顺序

| 阶段 | 优先验证的付费价值 | 合理的实验 |
| --- | --- | --- |
| V0 自用 | 暂不验证外部收费；先算清团队创作时间、绕行与维护成本 | 记录每件内部作品从空图到完成及后续修改的过程 |
| V1 | 节点创作更快、更易维护：私有项目、版本历史、可复用子图/预设、批量变体、团队协作 | 在可用编辑器基础上访谈具体创作流程，提供试点或专业功能报价；不要靠用户对抽象功能的“感兴趣”判断购买意愿 |
| V2 | 经验证的目标平台/管线生成、稳定升级、团队导出和集成支持 | 对明确目标配置的适配包或团队工作流收费试验，记录真实付款与适配器维护成本 |
| 后续 | 精选效果包、创作者市场与交易 | 等可编辑源图、许可、作品质量及供需成立后再引入 |

基础节点创作与可检验的实时预览应保留低门槛，以便证明核心价值。免费节点工具与引擎内置效果已经存在；收费要对应创作效率、维护或可靠适配的具体节省，而非仅仅是“能拖节点”。[Material Maker](https://materialmaker.org/) · [NixieFX](https://nixiefx.com/vfx-runtime-docs/) · [Construct 效果](https://www.construct.net/en/make-games/manuals/construct-3/project-primitives/objects/effects)

## 停线与转向

- **V0 自用不成立**：团队仍需手写 Shader 才能完成真实效果，或不愿持续使用自家工具；先修节点模型与生成链路，不做对外包装。
- **V1 创作不成立**：团队能用但外部用户只能修改模板，无法搭建自己的节点图；先修编辑模型、节点语义和学习路径，不扩目录。
- **所见不等于所得**：节点变更后网页预览与生成 Shader 不一致；先修同源生成/运行链路，不启动跨平台适配。
- **V1 留存弱**：大家只看示例、不保存或二次修改；研究是否需要更具体的效果任务或更易用的节点抽象。
- **V2 适配不可靠**：目标代码能生成，但在目标工程大量手改；收窄节点子集、平台或管线，明确目标专用作品。
- **跨管线成本过高**：同一引擎的不同管线需要大量特殊处理；对每条管线单独定价、排期或选择不支持，不宣称统一兼容。
- **付费只靠定制劳动**：把收入与可复用产品收入分开核算，不提前视为订阅模式已验证。

## 最近四项工作

1. 从[2D 游戏效果候选](./13-v0-2d-effect-candidates.md)中选 2–3 个近期确实要制作的作品；首个网页渲染目标已确定。
2. 写最小节点图语义、类型规则和“同一生成 Shader 驱动预览”的技术验证样例。
3. 做能连节点、生成、预览、保存重开的内部工作台；从空图用它完成第一个真实效果。
4. 持续用自用版做完其余效果，记录所有手工绕行与缺失能力；以这些证据划定对外 V1 的范围。
