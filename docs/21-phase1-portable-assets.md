# Phase 1 portable asset workflow

Round 12 completes the editor path for embedded project images. The left asset panel imports formal graph dependencies and shows their IDs, dimensions, and reference counts. A `Sample Image` node chooses one of those dependencies in the inspector. The preview panel separately imports and selects preview-only source images. Both paths use the same file decode and project-size validation; PNG, JPEG, and WebP are accepted up to 2 MiB per image, 3 MiB across the project, and 4096 pixels per dimension.

The project JSON embeds both lists under distinct `assets.dependencies` and `assets.preview` keys. Graph nodes refer only to dependency IDs; the preview scene refers only to a preview image ID. Importing or removing an image updates that scene or dependency list while leaving graph semantics explicit. Removing a referenced dependency yields a missing-image diagnostic and an **Old preview** instead of silently replacing the graph input. The unfinished graph remains saveable so users can repair it.

The Chrome WebGL2 end-to-end test builds a graph with a `Sample Image` node, imports a formal dependency and a separate preview source, selects Container, changes area/sampling/background/time and a runtime parameter, then saves to a project file. It reopens the file, compares generated build ID and canvas pixels, recovers a later browser draft, exports JSON, imports that JSON into a new editor session, and repeats the build/pixel check. Removing the dependency then verifies the missing-asset state and retained old pixels. Existing tests cover Phase 0 migration, bad import preserving the current project, picker cancellation, and size/duplicate-ID rejection.
