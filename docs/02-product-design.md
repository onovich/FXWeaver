# 体验与作品设计

更新：2026-09-30。第一步先做项目方自用版，让团队用网页低代码节点工具制作真实 Shader/效果；之后打磨对外第一版，再扩展第二版的平台适配。具体网页渲染后端和支持的效果类型仍待确定。

## 按版本呈现的产品层次

1. **自用版：内部节点工作台**。项目方从空图制作真实效果，连接节点、调参、实时预览、生成 Shader、保存重开，并在持续使用中修正节点和编译语义。
2. **第一版：对外网页创作工具**。将自用工作台打磨为外部创作者可独立使用的产品；项目方用同一工具制作的示例可帮助上手，用户能打开图、修改、换素材并派生。
3. **第二版：平台交付**。从同一源图选择平台、引擎版本和渲染管线，查看支持/降级/阻断原因，生成适配代码及运行时安装内容。

示例页可按视觉用途引导，但进入编辑器后节点画布是主工作区。编辑器不能只做模板换色：用户需要真正能从空图搭建、连接、修改和组合节点，且任何平台内 Shader 都由这套图生成。

## 核心路径

### 自用版：团队从零创作

`选择当前网页支持的效果类型 → 新建/连接节点 → 设置素材与参数 → 实时看到效果 → 检查生成 Shader/诊断 → 保存图 → 重开并继续编辑`

自用版的项目方必须能**从空图创作**，并用工具实际完成数个需要的效果，而非只制作演示模板。验收重点是节点变化与预览同步、保存重开一致、生成代码与当前网页所见结果对应；可先支持一个明确的网页渲染后端。对外第一版在此基础上补独立上手、错误说明、稳定性和文档。

### 第二版：适配与交付

`打开第一版源图 → 选择平台/引擎版本/渲染管线 → 查看能力检查 → 生成适配版本 → 在目标环境验证 → 下载代码/依赖/安装说明`

公开发布另有路径：`用节点工具创作 → 定义输入与参数 → 多场景预览 → 填写许可与说明 → 发布不可变版本`。初期公开示例只由项目方制作；开放外部投稿时仍要求作品由平台节点格式生成，并经过自动校验与内容审阅。

## 效果类型与作用范围

| 类型 | 处理对象 | 常见输入 | 版本范围建议 |
| --- | --- | --- | --- |
| 对象绘制材质 | Sprite/网格绘制阶段 | UV、原纹理、顶点颜色、对象变换 | 可作第一版候选；与滤镜不是同一种宿主 |
| 对象/容器滤镜 | 已绘制对象或图层的图像 | 输入纹理、滤镜区域、时间、参数 | 2D Web 第一版候选 |
| 全屏后效 | 相机或屏幕输出 | 场景颜色、分辨率；可能需要深度/法线 | 后续独立根节点与安装步骤 |
| 粒子效果 | 发射器、模拟与粒子绘制 | 生命周期、速度、随机数、贴图 | 后续资产类型，不等同于单个 Shader |
| 转场配方 | 两个场景/纹理及进度 | A/B 图像、进度、遮罩 | 可以借用滤镜/全屏图，但需运行时控制协议 |
| 3D 材质 | 表面与光照交互 | 法线、灯光、贴图、视角 | 长期方向，需要新能力与用户验证 |

界面上要持续显示当前作用范围，例如「应用于一个 Sprite」「应用于 Container 及其子对象」「作用于整个画面」。输入缺失时应具体说明，不能静默生成不适用的代码。

## 作品的数据卡片

第一版每件示例至少有：名称、实时预览、用途、图类型/作用范围、输入素材、暴露参数、可编辑节点源图及版本。第二版在平台适配出现后再补目标支持矩阵、性能条件、示例项目及目标验证时间；公开分享时还需作者、来源和许可。

分类采用**多个维度**而非互斥目录：

| 维度 | 例子 |
| --- | --- |
| 游戏用途 | 受击、技能、环境、UI、场景切换、状态效果 |
| 作用范围/资产类型 | Sprite 材质、对象滤镜、全屏后效、粒子、转场 |
| 风格 | 像素风、卡通、写实、故障风、手绘 |
| 目标能力 | PixiJS 版本/后端、Unity URP 版本、Godot 版本、移动端档位 |
| 交付约束 | 纹理输入、Pass、深度/法线依赖、授权方式 |

「像素风」是风格，「后效」是作用位置，「转场」是用途；同一作品可以同时具有这些标签。

## 效果页草图

示例页第一屏回答：**看起来如何、作用于哪里、能否打开图继续做。** 第二版再增加“能否用于我的目标项目”。页面结构可为：

1. 预览区：作者示例与用户上传素材切换；透明、深色、浅色、游戏场景背景。
2. 参数区：语义化参数和预设；显示动画时间点或播放控制。
3. 源图区：直接打开节点工作台、复制为草稿、派生版本；展示作者与 fork 来源。
4. 第二版兼容区：按平台、引擎版本和渲染管线列出已验证、部分支持、未支持及原因。
5. 第二版交付区：包内容、依赖、安装步骤、参数调用示例、许可证。
6. 诊断区：性能解释、已知视觉差异、测试条件及更新时间。

热门、点赞、评论可以后做。自用版先记录团队的「从空图创作」「成功生成/预览」「保存后重开」「修改节点后再生成」和不得不手写代码绕开的情况；第一版再记录外部用户独立完成率，第二版记录真实项目导入。

## 编辑器布局与交互

- **左侧**：节点与效果组件搜索，可按「纹理」「颜色」「形状」「动画输入」「合成」分组。
- **中央**：节点图；每种根节点明确输出用途。连接时显示端口类型，错误要指到具体节点和输入。
- **右侧**：选中节点的参数、可公开参数标记、单位/范围/默认值；同时显示此节点对输出和目标兼容性的影响。
- **预览区**：可换真实 Sprite/图集、背景、分辨率、时间、作用范围；能对比修改前后。首版可以与图画布并列或切换，不预设最终 UI 布局。
- **生成区**：第一版显示当前网页后端的生成 Shader、错误与可复制结果；第二版加入目标选择、支持状态、构建结果和工程安装说明。

默认工作台让用户直接搭建节点并持续看到结果；示例效果提供快速起点，但不能替代节点创作。生成代码可查看和复制。原始代码节点可能绕开“平台 Shader 均由节点工具生成”的统一语义，暂不列入第一版；如以后支持，需另定校验与跨目标规则。

## 性能与预览的可信表达

性能提示分三层：

1. **静态可解释指标**：纹理采样次数、额外 Pass、循环/分支、临时缓冲区。
2. **场景成本条件**：滤镜覆盖面积、分辨率、实例数量、同时播放数量。
3. **真实测量**：指定设备、浏览器/驱动或引擎版本、测试场景下的帧时间与视觉截图。

不要把静态估计冒充普适 GPU 耗时。跨不同引擎的预览比较应给出差异和容差，而不是无条件宣称逐像素一致。

## 社区规则的阶段设计

- **阶段一**：自用版由项目方用同一节点工具制作真实效果；对外第一版可开放这些示例及其源图，完整社区功能后置。
- **阶段二**：按需求增加用户私有作品与 fork、派生链接，保留原作者与版本来源。
- **阶段三**：邀请制创作者发布；投稿必须含可解析源图、许可声明、输入说明和自动目标检查。
- **阶段四**：视采用与供给质量考虑公开投稿、审核工具、付费作品和收益分配。

每个版本不可变更其已发布源图；更新要产生新版本，避免别人引用的效果在无通知下改变。作品的代码许可、预览素材和封面素材授权应分别清楚。
