## 2. 本阶段要完成什么

### 2.1 单一生成链

`版本化图 + 明确的素材依赖 → 现有图校验 → 类型化中间表示 → 确定性 GLSL/资源清单/节点映射 → PixiJS Filter 编译与绑定 → 同一构建的预览和只读代码视图`。图、生成器版本、后端版本与编译期设置决定构建身份；画布布局不参与。预览时间和运行时参数值有单独可追踪的状态，改变它们时可更新 uniform 而不伪造新代码构建。失败时保留上次成功画面但显著标为“旧预览”，并显示当前错误与旧构建 ID。

公共数学、采样、颜色、时间和输出节点必须足够让三件作品从空图拼出，避免 `Burn`、`Melt`、`Hologram` 等效果专属内置节点或代码分支。节点类型与转换规则显式；至少能处理源内容 RGBA 与 UV、额外纹理采样、数值和颜色参数、时间、算术、三角/距离、阈值/平滑、混合、通道拆组以及 RGBA 输出。按作品真实需求增补，避免堆与作品无关的节点。无效图可以保存，但不能标记为构建成功。

### 2.2 预览和工程

- 新建正式 Filter 图时自动有唯一输出根；选择 Sprite 或 Container 测试宿主、透明素材、背景、滤镜区域/边距、分辨率与采样设置。界面明确：Filter 采样的是宿主已绘制内容，不等于 Sprite 原图集 UV，也不能读取滤镜外的背景。
- 图变化触发校验和异步生成/编译；并发结果只能由最新请求采纳。播放、暂停、归零、固定秒数与参数拖动可检查动态效果。显示生成中、成功、失败、旧预览、WebGL2 不可用和素材缺失状态。
- 工程文件携带图、稳定参数 ID、正式依赖素材、预览专用素材/场景、时间与设置。图/工程版本迁移应使 Phase 0 的 `foundation.test` 文件仍能无损打开，旧文件不得静默升级成 Filter；导入、保存、重开、草稿恢复及取消文件选择均继续可靠。大素材如需限制体积，给出可理解的上限与错误。
- 代码区只读，展示本次预览实际使用的生成 GLSL、参数/纹理绑定表、后端和构建 ID；仅成功构建可复制或下载对应结果。不能把代码手改成作品来源。

### 2.3 首批三件作品

| 编号 | 用途与作用对象 | 必须由图覆盖的行为 | 验收界限 |
| --- | --- | --- | --- |
| **03 径向燃烧／烧蚀** | 调查 UI / 拼图内容的局部显隐与边缘燃烧 | 源内容 + 噪声纹理、中心/半径或进度、边缘宽度/颜色、透明裁切 | 透明边、中心移动、进度变化可见；不承诺复刻 Unity UI Stencil |
| **05 局部溶融／波纹扭曲** | 第一章 UI / 局部转场容器 | 时间、频率、振幅、强度驱动 UV 偏移，并重采样宿主输入 | 暂停和固定时间稳定；明确越界采样行为；不做 URP RenderGraph |
| **09 局部全息扫描／信号故障** | 调查终端或局部 UI 图层 | **一个**局部形态：扫描线、有限通道错位、强度/时间/种子或遮罩 | 作用范围及成本可控；不做整屏 CRT、多变体肖像、图集投影或历史帧 |

每件作品都须有编辑器从空图创作的操作证据、可编辑 `.fxweave.json` 工程、生成代码/构建清单、固定参数和时间的预览记录。若现有 Unity 素材不适合直接入仓库，用仓库内可许可的合成测试素材；不要复制未授权资产。至少展示一次修改关键连线/属性后画面变化、保存重开后构建与固定画面等价。推荐先以 03 建立完整纵切面，05 验证时间与 UV，09 验证组合能力与性能边界。

## 3. 本阶段不做什么

- 不做 Unity Shader 翻译/导出、URP/HDRP、WebGPU/WGSL、多个渲染管线、真正 Sprite 材质、全屏合成或多 Pass 效果。
- 不把 PixiJS 现成滤镜、`pixi-filters`、原 Unity Shader 或手写效果 GLSL 放进作品运行路径。它们可以作研究/视觉对照；基础通用 Shader 包装和生成器模板允许由代码实现。
- 不做自定义代码节点、任意循环、外部 Shader 注入、AI/MCP、社区、账号、云存储、发布与交易。
- 不以截图、静态原画或独立 JavaScript 解释器冒充节点生成 Shader 的实时画面。

## 4. 每轮固定工作流

每轮开始检查 `git status --short --branch`，确定本轮最小交付，再执行：

- **Debug 自检**：用最小图或最短 UI 路径复现变化；定位图解析/校验、IR、代码生成、WebGL 编译、资源绑定、预览状态或持久化层；检查成功、失败、空、旧结果、不兼容和缺失素材等相关状态；UI 改动补可重复 Chrome smoke，状态/格式改动补保存、导入、迁移边界验证。
- **架构自检**：节点图仍是唯一源；节点定义、IR、代码生成、宿主绑定、预览和 UI 职责分离；UI 不复制 Shader 或图规则；图语义哈希不受布局影响；生成器没有按效果名分支；预览与只读代码来自同一构建；不越过 V0 Filter 范围，不碰无关文件和用户改动。
- **验证**：运行本轮相关 `npm run typecheck`、`npm test`、`npm run build`、`npm run smoke` 或专门的浏览器 WebGL2 测试，记录命令与结果；提交前执行 `git diff --check`。WebGL2 实测失败不能用 mock 的测试通过替代。

每轮报告必须有：轮次、目标、完成内容、Debug 自检、架构自检、验证命令及结果、commit hash、push 结果、下一轮目标、是否消耗缓冲轮。验证失败不得提交；提交或推送失败不得进入下一轮。

## 5. 每轮通过后提交推送工作流

沿用仓库当前 Git 工作流。每轮验证通过后运行 `git status --short --branch`、`git diff --stat`，只定向暂存本轮文件，提交并推送，再核对工作区与远端分支。不要暂存缓存、录证临时文件、无关 untracked 文件或 `UnregisteredScene` 文件。记录完整 commit hash 和推送结果。推送失败时停止并向规划验收会话报告错误；修复并成功推送后才能推进下一轮。协作期间不要重写别人的提交或强推。

## 7. PASS 标准与验证矩阵

1. **同源生成**：三件作品都能由正式图种类从空图搭出，代码视图与 Pixi 预览是同一次生成构建；源码中无按作品名分支、内嵌效果 Shader 或独立效果解释器。保存重开后的生成代码/清单和固定场景等价。
2. **真实交互**：改拓扑、常量、参数、素材和时间时，画面按相应语义改变；暂停后的画面保持固定；生成中、失败、旧画面、素材缺失和 WebGL2 不可用均有准确反馈。
3. **正确边界**：Filter 宿主范围、UV、透明、预乘 Alpha、额外纹理和边缘采样有记录的 WebGL2 实测。03 的透明裁切、05 的 UV 重采样和 09 的局部通道/扫描均可在固定输入下观察；不宣称 Unity 画面像素级一致。
4. **工程完整**：每件 `.fxweave.json` 源图、依赖素材、预览场景、参数及布局可搬迁并继续编辑；Phase 0 `foundation.test` 工程仍可打开；不兼容文件不会破坏当前工程。示例原件可派生且不会被覆盖。
5. **可复验**：类型检查、单元/集成测试、生产构建、桌面 Chrome smoke、三件效果的真实 WebGL2 浏览器演示全部通过。有固定画面/录屏、源码与构建身份、可重复步骤，以及每轮提交推送记录。
6. **自用反馈**：记录三件作品的实际搭建步骤、耗时、绕行与缺失节点。自用版产品规格要求的“隔天继续编辑”需在真实跨日使用后单列验证；本阶段 20 轮技术 PASS 不能凭一次模拟重开声称这条已经完成。
