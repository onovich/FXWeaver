# FXWeave 自用版：功能与交互设计

更新：2026-09-30。状态：**产品设计建议稿**。这里的“自用版”暂称 V0，是项目方实际拿来制作 Shader/效果的内部网页工作台；对外网页 V1 在它的创作内核上打磨，V2 再扩展平台和渲染管线适配。[路线图](./06-roadmap-proposal.md)

## 1. 目标、使用者与边界

### V0 必须完成的任务

团队成员从空节点图开始，制作一个真实要使用或展示的效果；更换测试素材，调参数，看到由当前图**生成的 Shader** 实时渲染；保存工程，隔天打开继续修改；取得当前网页目标的生成代码与参数/素材说明。项目方制作的所有示例 Shader 都从这套工具生成，不在工具外手写 Shader 来补齐作品。

V0 的“所见即所得”限定在**已选的 PixiJS 8 WebGL Sprite/Container Filter**。这是一类处理宿主已绘制内容的效果，其他宿主需要不同根节点、输入和预览场景。预览需能检验滤镜作用范围、透明边和纹理采样；PixiJS 官方文档确认 Filter 可应用于 Sprite/Container，纹理还有 frame、trim、alphaMode、scaleMode 等语义。首批效果待从[候选清单](./13-v0-2d-effect-candidates.md)选定。[PixiJS Filter](https://pixijs.com/8.x/guides/components/filters) · [PixiJS 纹理](https://pixijs.com/8.x/guides/components/textures)

V0 内部创作者同时是产品的第一批使用者。优先保证**做得出、改得动、存得住、结果一致**；视觉装饰和社区机制按这些任务的实际卡点再排序。

### V0 的完成判据

1. 团队用 V0 从空图完成至少 2–3 件近期确实需要的、结构不同的效果；图和生成 Shader 一起保留。
2. 每件作品的关键外观可通过节点连接或参数更改获得，生成代码没有手工补丁。
3. 同一图保存并重开后，生成代码、参数定义和固定预览场景等价；改图后的画面来自新生成的 Shader。
4. 每件作品至少经历一次隔天继续编辑，记录缺失节点、错误、绕行和完成时间。项目方愿意继续用它做下一件效果。

## 2. 信息架构与工作台布局

V0 只需要两个主页面：**项目入口**与**编辑工作台**。固定在桌面浏览器使用，建议设计基准为 1366×768 或更宽；窄屏可折叠侧栏，不把手机触控编辑作为首轮验收条件。

```text
项目入口
├─ 新建效果（当前已支持的宿主，V0 初期只有一项）
├─ 打开本地工程 / 最近工程 / 恢复意外关闭的草稿
└─ 团队示例图（必须能在编辑器中打开并继续改）

编辑工作台
┌ 顶栏：工程名 · 当前宿主/网页后端 · 保存状态 · 撤销/重做 · 生成状态 · 保存 · 输出 ┐
├ 节点与素材栏 ─┬────────────── 节点画布 ──────────────┬─ 实时预览 ─┤
│ 节点搜索/分类  │   连接、框选、缩放、平移、错误标记     │ 素材/场景/时间 │
│ 素材输入列表   │                                     ├──────────────┤
│               │                                     │ 属性检查器     │
└───────────────┴─────────────────────────────────────┴──────────────┘
底部可展开：问题列表 / 只读生成代码 / 参数与资源清单
```

画布与预览**默认同时可见**，分隔条可拖动调整宽度。选中节点时右下显示节点属性；未选节点时显示工程级设置与暴露参数。预览永远标明当前使用的是哪一次成功构建。节点库和素材库可切换，保持同一位置，减少鼠标往返。

## 3. 功能清单与交互契约

| 模块 | V0 功能 | 关键交互与反馈 |
| --- | --- | --- |
| 工程入口 | 新建、打开、最近使用、复制工程、恢复草稿 | 新建自动放入唯一输出根节点；打开前若当前图未写入工作文件，提示保存/放弃；最近工程显示宿主与最后修改时间 |
| 节点画布 | 节点搜索、添加、移动、连线、断开、框选、复制粘贴、删除、平移缩放、适配视图 | 双击空白处打开搜索；拖动输出端口时只高亮兼容输入；不兼容落点拒绝并解释；所有结构操作可撤销/重做 |
| 图约束 | 唯一输出根、端口类型、必填输入、无环、宿主能力检查 | 无效连接当场阻止；允许保存未完成的图，但无效图不生成新 Shader；问题定位到节点与端口 |
| 节点属性 | 常量/颜色/向量/纹理输入、单位、范围、默认值 | 选中节点后编辑；滑杆拖动时节流预览，松手只记一条撤销；数字输入 Enter 提交、Esc 取消；非法值保留原值并提示 |
| 暴露参数 | 把支持的数值、颜色、向量标为运行时参数 | 给参数稳定 ID、名称、类型、默认值、可选范围；预览面板可直接调；生成结果附参数绑定清单；重命名显示可能影响调用方的提示 |
| 素材 | 导入本地图片、给纹理输入绑定素材、替换/移除、查看尺寸与透明信息 | 拖文件到素材栏或点导入；缺失输入显示占位和错误；预览用素材与作品正式依赖分开标识，避免把测试背景误当 Shader 输入 |
| 实时预览 | 同一生成 Shader 驱动的画面、深/浅/棋盘背景、缩放与适配、时间播放/暂停/归零/拖动 | 图或参数变更后标记“生成中”；成功切换到新结果；失败保留上次成功画面并显示“旧预览”，绝不把旧画面当新结果 |
| 诊断 | 图错误、Shader 编译错误、生成耗时、基础静态成本 | 顶栏显示成功/生成中/失败；底部问题列表点一项聚焦节点；编译错误尽量映射到节点；静态成本只列采样数等可解释事实，不冒充 GPU 耗时 |
| 生成结果 | 当前网页目标的只读 Shader、参数/素材清单、构建标识 | 仅成功构建可复制/下载当前结果；显示源图版本、生成器版本和构建哈希；从生成代码不能反向编辑源图 |
| 工程持久化 | 保存、另存为、自动恢复草稿、导入/导出完整工程 | 明确区分“已保存到工作文件”和“仅有本机恢复草稿”；工程包带图、素材、预览场景、元数据；恢复草稿时可比较时间并选版本 |
| 内部示例 | 团队用工具制作的若干示例图，打开后另存副本 | 示例保持只读原版，修改前自动成为副本；示例页标注当前宿主、输入要求和图版本 |

### 节点画布的细节

- 端口类型至少区分 `float`、`vec2`、`vec3`、`vec4/color`、`texture`。颜色与一般向量的转换要有明示规则；V0 不做会改变语义的隐式转换。
- 每个输入端口至多接一条线；把新线放到已有连接上时先替换，操作可撤销。拖空旧连线可断开。多选移动视作一条撤销记录。
- 输出根由新建工程自动创建并固定为唯一，根节点说明该 Shader 作用位置与输出值。无有效输出时右侧明确显示“等待连接输出”。
- 节点搜索可按名称与用途匹配，列出端口签名。V0 的节点集合从团队实际制作的 2–3 个效果反推，不靠堆数量验收。
- 画布状态（节点位置、缩放、选中状态）可以恢复，但不影响 Shader 语义与构建哈希。

### 预览与参数的细节

- 预览场景保存测试素材、背景、画布尺寸、缩放、宿主、时间点及暴露参数值；允许一键在“默认素材”和“当前素材”之间切换。
- 时间有播放/暂停、归零、单步或拖动到指定秒数。图中的时间节点使用同一时间定义；暂停后修改节点不应悄悄推进时间。
- 参数拖动只更新运行时 uniform 时可直接刷新；拓扑和编译期值改变才重新生成/编译。无论哪一种，预览标识必须与当前图/参数状态对应。
- “原图/效果”切换可帮助判断作用位置；此处的“原图”指同一素材未经当前 Shader 处理的对照，不是另一套效果实现。
- 预览增加 Sprite/Container 宿主与作用边界显示，并可调测试用的滤镜区域/边距、采样方式和分辨率；这些是宿主相关设置，不作为所有 Shader 图的通用节点。[PixiJS Filter](https://pixijs.com/8.x/guides/components/filters) · [PixiJS 性能提示](https://pixijs.com/8.x/guides/concepts/performance-tips)

## 4. 首发节点与效果宿主

**先固定一个图类型**。V0 的节点库只覆盖团队选定的效果任务，但要支持从空图组合出不同结构。以下是“2D 对象/容器 Filter”图的候选最小集，需用选定作品删减或补充：

| 类别 | 候选节点/输入 | 用途 |
| --- | --- | --- |
| 宿主输入 | 源图像、UV、像素尺寸、时间 | 明确 Filter 所能读取的输入 |
| 常量与参数 | 标量、向量、颜色、外部纹理参数 | 制作可调效果和运行时绑定 |
| 运算 | 加减乘除、最小/最大、Clamp、Step、Smoothstep、Mix | 颜色、遮罩、阈值及边缘过渡 |
| 坐标与采样 | UV 偏移/缩放、采样源图、采样额外纹理 | 扭曲、噪声遮罩、邻域采样 |
| 颜色与透明 | RGB/RGBA 合成、Alpha 提取/乘法、颜色混合 | 保留透明语义并组合结果 |
| 输出 | 唯一 Filter 颜色输出 | 指定最终 RGBA |

候选首批作品可覆盖“颜色变化”“随时间推进的遮罩/溶解”“需要边缘或邻域采样的效果”，但最终应选团队近期**真正要用**的作品。若某个效果需要循环、多 Pass、深度缓冲或自定义代码才能成立，需明确记录为新的宿主/能力需求，不在 V0 中把它伪装成普通节点。

## 5. 关键操作流程与状态

### A. 从空图制作第一个效果

`项目入口 → 新建 → 自动创建输出根 → 双击画布搜索节点 → 连接输入/运算/输出 → 右侧实时预览 → 调属性与时间 → 标记暴露参数 → 保存工程 → 查看并输出生成结果`

创建项目时默认打开一个可用的测试素材与棋盘背景，预览显示未连接输出的明确空状态。第一次成功连接输出后，顶栏出现“生成成功”和构建标识。用户不需要先填写作品名称、分类或许可才能开始创作。

### B. 修改后编译失败

`更改节点 → 图校验/编译失败 → 画布节点标红 + 问题列表 → 预览保留上次成功结果并标“旧预览” → 点击问题聚焦节点 → 修改或撤销 → 再次生成成功`

错误按图结构、语义、素材缺失、后端编译四层归类。若底层编译错误不能精确定位，至少展示生成代码行号和相关节点集合；不能静默失败或用旧预览冒充成功。

### C. 保存、关闭、恢复与输出

`Ctrl+S 保存当前工作文件 → 顶栏显示保存位置/时间 → 关闭/刷新 → 最近工程打开 → 检查固定预览场景 → 继续编辑`

推荐 V0 团队统一用桌面 Chrome/Edge 的文件读写能力维护一个完整工程包；不支持该能力时可使用导入/下载。首次选文件和恢复写权限由用户操作触发，应用须显示取消或拒绝后的保存状态；该 API 在支持的浏览器中要求安全上下文。[Chrome File System Access 文档](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access/) · [MDN `showSaveFilePicker`](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker) 浏览器本机恢复草稿只用于防意外关闭，**工程包才是可搬迁的正式保存物**。工程包至少含 `schemaVersion`、`graphKind`、`rendererTarget`、节点/边、暴露参数、素材、预览场景及生成器版本。生成代码可随包携带以便复核，但始终可由源图重新构建。

### D. 用内部示例派生

`打开团队示例 → 查看完整节点图 → 另存副本 → 替换自己的素材/改节点 → 实时预览 → 保存为新工程`

示例只从团队 V0 工程导入，不允许只有图片/录屏或单独生成代码。示例原版与派生副本有不同 ID，避免修改时覆盖原版。

## 6. 快捷操作与基础可用性

| 操作 | 建议快捷键/交互 |
| --- | --- |
| 保存 | `Ctrl+S`，Mac 对应 `Cmd+S`；顶栏也有按钮 |
| 撤销/重做 | `Ctrl+Z` / `Ctrl+Shift+Z`；按钮显示可用状态 |
| 添加节点 | 画布空白处双击，输入名称搜索；素材可从左栏拖到对应输入 |
| 删除 | 选中后 `Delete`；输出根不允许删除 |
| 复制/粘贴/重复 | `Ctrl+C/V/D`；复制保留内部连线并分配新节点 ID |
| 平移/缩放 | 空格拖动画布；滚轮以指针为中心缩放；`F` 适配全部节点 |
| 聚焦错误 | 点击问题列表项定位并选中节点 |

所有关键动作同时有可见按钮或菜单，快捷键只是加速。编辑数值时快捷键不应抢夺文本输入；删除连线、删除节点和覆盖文件有明确撤销或确认路径。预览、错误和保存状态不能只靠颜色表达。

## 7. 验收清单

1. **真实创作**：团队从空图完成选定的 2–3 个效果；源图打开后可继续编辑，生成 Shader 不含人工补丁。
2. **同源所见即所得**：修改节点拓扑、常量和运行时参数分别触发正确更新；固定图、素材、时间和参数可重现画面。
3. **失败可恢复**：制造类型不匹配、缺失输入、环、无效素材和后端编译错误；每种都有清楚反馈，旧预览标为旧，撤销后能恢复。
4. **存储可靠**：带素材的工程保存、关闭、重开后图、参数、预览场景和生成结果等价；恢复草稿不会覆盖正式工作文件。
5. **输出可追溯**：生成代码、参数清单和素材依赖能关联源图版本、后端和构建标识；只读代码视图与实时预览使用同一次成功构建。
6. **持续自用**：至少一件效果经历隔天修改，团队记录制作时间、缺失能力和绕行；这些记录决定对外 V1 的优先级。

## 8. 已定首个目标与仍待确定的事项

1. **已定首个效果宿主与网页后端**：PixiJS 8 WebGL 的 Sprite/Container Filter。具体 PixiJS 小版本须在开发指南中锁定，Filter 与纹理语义写进图类型和预览测试。
2. **首批真实效果**：从[2D 游戏效果候选](./13-v0-2d-effect-candidates.md)中选 2–3 个，并说明实际用途与作用对象。
3. **团队正式工作文件位置**：V0 建议本地完整工程包加浏览器恢复草稿；若团队已有统一仓库，可把工程包纳入版本管理。

后续增加其他宿主时，需扩展宿主相关节点、预览与输出契约；“图是源文件，生成 Shader 驱动预览”的核心交互不变。
